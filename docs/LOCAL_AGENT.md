## Bounded orchestration

`POST /api/director/assignments` starts one local assignment at a time and returns its run ID. `GET /api/agent/runs/{id}` exposes actual stage/events. Local account inference requires `BANKING_STUDIO_LOCAL_AGENT=1`; the separate `BANKING_STUDIO_EXTERNAL_CONNECTIONS` gate can remain zero. The run is not represented as completed merely because a model process started.

1. A structured planning request receives the director's public instruction, supported financial methods and entity universe, and the current brief/terms for a follow-up. It proposes the brief, storyline, missing-input qualifications and explicit scenario changes. Unsupported entities or methods produce clarification with no generated-materials claim.
2. The host validates the brief and terms. New work obtains company/rate observations through the actual MCP pool adapter, runs deterministic Rust calculations, retains models and prepares a source-bound document. Public refresh is an explicit bounded ingestion option; errors are recorded and do not become live-data claims. Bond actions can be deliberately sized to the same stated net-cash requirement. Financial revisions use the same validated typed endpoints as inspected edits.
3. A second bounded model request receives selected financial context, active method outputs/warnings, peer context, public bank proposition, existing document and review issues. It proposes a complete semantic document: headlines, narrative and typed financial frames. Authoritative numbers are never taken from generated narrative. Required client-decision/conditions/comparison and assumptions/source sections remain validated.
4. The host separates dense evidence frames into full pages without discarding authored content, enforces a maximum document size and compiles the brand scene. Invalid prose, references, density or stale revisions refuse the generated replacement. Existing saved work remains available; a valid financial revision completed before a later composition failure remains an explicitly review-required revision.
5. Generated work is a proposal. It does not create a banker preference, sign review declarations, verify issues or freeze a discussion copy automatically. Subsequent generated changes reopen prior dispositions for review. Original financial outputs, history and frozen copies remain preserved.

Each stage has a ten-minute model timeout, a five-second heartbeat and explicit cancellation. The model process runs in a new private temporary directory, ignores user configuration, uses a read-only sandbox, disables the shell tool and web search, and receives public context on stdin. The app does not load the Codex token file; CLI authentication remains owned by Codex. API-key environment variables are removed from this child so the intended local login route is used. Schemas and temporary files are removed after the request. These are prototype boundaries, not a bank sandbox/security acceptance claim.

`GET /api/director/status` reports enabled state, sanitized local-login checks, two fixed profiles and saved multi-source settings. The default is **Codex gpt-6.1-sol / High**. The alternative is **Claude Code Opus / Medium**, using its own saved local authentication and a tool-free, strict-empty-MCP invocation. API-key environment variables are removed from either child. A signed-in account does not establish available quota: the actual Claude readiness rehearsal on 23 October returned `usage_limit_reached`; no successful Claude generation is claimed. The app does not silently substitute providers. `POST /api/director/settings` saves profile/source selection; every run snapshots the actual selection. `GET /api/director/jobs` restores the latest assignment after a reload; cancellation and terminal feedback remain visible outside the assignment page.

## Data pool and ingestion

`public_pool` is an append-only set of normalized source versions and hashes. The public archive seeds company/rate versions; successful fixed-host public refreshes append retained versions. Workroom retrieval selects the latest pool version and then pins the observations in its own source snapshot. Refreshing the pool does not rewrite an existing client calculation. Original reported values, tags, periods and filing references remain available.

`ingestion_jobs` records fetching, success/failure and pending document-extraction jobs. SEC, Apple issuer-report, Treasury, Bundesbank and NYU hosts/paths are constructed by code; users cannot ask this adapter to fetch an arbitrary internal URL. Public report URLs on supported public hosts can be registered, but registration is not download/extraction, reviewed facts or numerical model input. A reviewed, report-specific Apple 2025 annual-report HTML adapter feeds eight canonical facts, including the carrying-value debt components. Generic report extraction, richer parsing/normalization and promotion controls remain next phase. The current receipts retain normalized financial observations and provenance, not a complete raw-document warehouse.

The app remains a modular monolith. An agent orchestrator, ingestion adapters, canonical data/evidence, deterministic methods and semantic rendering are separate responsibilities even when one lightweight binary hosts them. Future API, SDK, provider-MCP or native-shell adapters should preserve these boundaries.

## Guided discovery and contextual evidence (M16)

The primary UI starts `POST /api/director/assignments` with `discoverOnly:true` and `useRecommendedSources:true`. A completed `awaiting_direction` result holds model-proposed questions and an evidence plan, without creating materials. Continue through the same endpoint with `intakeId` and `directionAnswers`; the server validates required answers and the native model refines the brief. Current saved connections control the continuation.

Core evidence needs vary by method; additional catalogued needs and mapped peers come from the agent. The host intersects them with enabled sources, ingests fixed public endpoints and retrieves market/credit context through the ninth MCP tool. New delayed-price baselines are conditional and source-bound; historical issuance spreads are never current spread observations. Semantic evidence/history/credit/equity frames remain validated.
