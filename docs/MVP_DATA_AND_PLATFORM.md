# MVP data access and deployment choices

Verified against public primary documentation on 22 October 2026. Public offers are not a confirmation of this owner's entitlement, onward-use rights or bank approval. No trial account was opened, purchase made, supplier contacted or bank integration attempted.

## Recommendation for the external MVP

Use **SEC company facts plus U.S. Treasury observations**, with explicit analyst assumptions for stock execution prices and corporate credit spreads. This costs no data-subscription fee and is implemented in the local demo. The sources are authoritative for reported filings and government yields, but do not provide consensus estimates, adjusted EBITDA, complete transaction comparables or executable corporate-bond prices. A genuine public-data financing scenario is possible; a free institutional-quality cross-asset data stack has not been established.

The application contains a small normalized snapshot for PepsiCo, Campbell’s and General Mills. Financial facts retain original units, period, filing date, accession and XBRL tag. Amounts are converted to USD millions in the engine; the source value remains available. The app uses a dated Treasury curve. Stock prices, deal shares and credit spreads are visibly editable assumptions, never silently represented as market observations. [SEC API documentation](https://www.sec.gov/search-filings/edgar-application-programming-interfaces), [Treasury feed documentation](https://home.treasury.gov/treasury-daily-interest-rate-xml-feed).

For the first paid-data evaluation, request only three issuers, annual/interim financials, dated equity closes, bond reference terms, dated observed prices/yields/spreads, and source/vintage metadata. Ask specifically for external prototype display, derived analysis, export, short-term caching and external AI processing rights. **MCP is a tool interface, not the data licence or a guarantee of consistent financial definitions.** Do not delay the Monday public-data demonstration waiting for an institutional trial.

## Can an existing Microsoft 365 Copilot subscription power it?

**Potentially, through the Microsoft 365 Copilot Chat API preview.** Microsoft's specific API documentation says it is available at no additional cost to users with the Microsoft 365 Copilot add-on licence. It returns text; it does not generate files, execute actions, expose a code interpreter, or support long-running jobs. This application would continue to own calculations, orchestration, revision history and exports. This is distinct from free Copilot Chat or an arbitrary reusable Azure OpenAI token. [Chat API overview](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/api/ai-services/chat/overview).

The documented `/beta/copilot/conversations/{id}/chat` route supports delegated work/school accounts, not application-only or personal-account access. The reference currently requires **all** listed scopes: `Sites.Read.All`, `Mail.Read`, `People.Read.All`, `OnlineMeetingTranscript.Read.All`, `Chat.Read`, `ChannelMessage.Read.All` and `ExternalItem.Read.All`. Those are substantial permissions for this narrow application and require tenant/security assessment. Beta APIs are not supported for production use. [Endpoint and permissions](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/api/ai-services/chat/copilotconversation-chat).

Inference: a proof of concept may reuse eligible licensing if tenant policy permits registration/consent and the preview is acceptable. Possession of a Copilot licence alone does not establish that permission. This MVP has no Microsoft login or Copilot adapter; actual Rabobank tenant configuration is unknown. Enterprise data protection, no-training terms, retention controls and ZDR are different claims and must be verified for the actual processing route.

## Efficient native Windows and macOS path

The revised MVP uses **Rust + SQLite + React/TypeScript**. Calculations and state management execute in Rust; React and the browser handle the interface; the Tiptap editor is loaded only when needed. Node/npm are build tools, not runtime services. There is no bundled Chromium, Node server, Python service, local LLM or background polling when idle. The browser polls only while a revision job is active. Backend HTTP I/O is asynchronous with two runtime worker threads; database work is small and serialized.

Rust is a practical choice for a fast, memory-conscious native core, not a claim that one language is universally fastest. Network/model latency, database access, document rendering and workload size often matter more. The measured backend footprint is in [verification.json](verification.json); browser memory is explicitly excluded. Managed-laptop performance has not been measured.

Next, wrap the same interface with an operating-system webview (for example Tauri), compile separate Windows/macOS binaries, and use user-profile storage. Tauri documents its Rust/webview architecture and platform prerequisites. A per-user installation can be technically possible, but code signing, notarization, endpoint allowlisting, WebView2 availability and the bank's software-distribution policy determine whether admin rights or managed installation are required. [Tauri architecture](https://v2.tauri.app/concept/architecture/), [distribution](https://v2.tauri.app/distribute/), [Windows prerequisites](https://v2.tauri.app/start/prerequisites/#windows).

The current Apple Silicon `.app` is only a local unsigned launcher for a loopback web application. It is not a Tauri app, Windows package or bank-managed deployment. Retain the lightweight web version as a deployment option if managed native packaging is slower to approve. Select the approved model route separately; the presentation and financial core need not change when an approved API replaces the external demonstration API.
